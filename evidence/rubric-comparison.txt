navidrome project-02 插件设置候选切换
Rubric ID：1｜状态：未通过｜期望行为：已禁用插件的配置或权限更新仍只持久化设置而不创建实例或 host service；按现有规则移除必需权限时仍可明确禁用。｜实际观察：已禁用插件只持久化设置；但运行插件移除必需权限时先调用 unloadPlugin 关闭旧实例，随后 repo.Put 失败会返回错误且旧实例已经停止。｜直接证据：plugins/manager.go:573-582 的执行顺序为 unloadPlugin、设置 Enabled=false、repo.Put。｜原因：权限移除路径在数据库提交前卸载旧实例｜影响：数据库失败后持久设置仍为旧启用状态，当前进程却已失去旧活动实例，禁用提交没有同成败。｜证据位置：plugins/manager.go:573-582
Rubric ID：2｜状态：通过｜期望行为：运行插件的新配置在编译、实例创建、host service 建立或生命周期初始化任一步失败时，候选资源全部释放，旧实例和旧设置继续可用。｜实际观察：编译、实例创建、host service 建立和 init 都发生在未发布候选中，失败路径调用 closeAll、compiled.Close 或 candidate.close。｜直接证据：plugins/manager_loader.go buildPluginCandidate 的 defer 清理与 plugins/manager.go init 失败清理；候选测试和带 fts5 测试通过。
Rubric ID：3｜状态：通过｜期望行为：候选实例已验证但持久配置提交失败时不会切换活动实例或发送成功刷新，管理 API 返回错误且重启后仍加载旧成功配置。｜实际观察：运行插件设置先构建候选，commitCandidate 的 repo.Put 失败会关闭候选且不替换活动 map，也不发送成功刷新。｜直接证据：plugins/manager.go updatePluginSettings 与 plugins/manager_loader.go commitCandidate；DB 失败测试通过。
Rubric ID：4｜状态：未通过｜期望行为：成功更新使配置、用户或媒体库权限、活动实例和可观察插件能力只切换一次，之后旧实例及其调度、WebSocket、任务队列等资源被完整关闭。｜实际观察：commitCandidate 在数据库写入和 map 替换后调用 destroyPlugin；destroyPlugin 对 plugin.Close 和 compiled.Close 错误只写日志，调用者仍返回成功。｜直接证据：plugins/manager_loader.go destroyPlugin 的错误分支均为 log.Error，没有向 commitCandidate 返回错误。｜原因：旧实例资源关闭失败只记录日志且成功更新仍返回成功｜影响：旧调度、WebSocket、任务队列或编译实例关闭失败时，管理 API 报告成功且资源回收没有完成。｜证据位置：plugins/manager_loader.go:586-608
Rubric ID：5｜状态：通过｜期望行为：初始化函数返回错误会被视为候选加载失败而非仅记录日志，LastError、Enabled、API 响应和刷新事件与实际仍在运行的代际一致。｜实际观察：callPluginInit 返回错误，候选被关闭，旧代保持活动，错误被写入 LastError 并返回管理接口。｜直接证据：plugins/capability_lifecycle.go 与 plugins/manager.go 的 init 错误分支；候选 init 失败测试通过。
Rubric ID：6｜状态：通过｜期望行为：同一插件的并发设置更新按确定顺序提交，迟到的成功或失败不会覆盖更新的持久状态、替换新实例或关闭错误代际。｜实际观察：同一插件更新由 pluginOpLock 覆盖读取、构建和提交，commitCandidate 还校验 expected 活动指针。｜直接证据：plugins/manager.go pluginOpLock 与 plugins/manager_loader.go errPluginGenerationConflict；并发候选测试通过。
Rubric ID：7｜状态：未通过｜期望行为：成功更新后服务重启加载最后提交的设置；连续失败后再次保存有效设置能够恢复切换，且没有遗留候选 goroutine、文件句柄或重复 host service。｜实际观察：候选 close 与旧代 destroyPlugin 都吞掉 Close 错误并仅写日志；连续保存能够再次构建，但遗留资源没有登记和重试所有者。｜直接证据：plugins/manager_loader.go pluginCandidate.close 与 destroyPlugin 均无错误返回。｜原因：候选和旧代资源关闭错误不会使更新失败或形成可重试状态｜影响：关闭失败的 goroutine、文件句柄或 host service 可在成功响应后继续存活，后续保存和重启前没有确定清理闭环。｜证据位置：plugins/manager_loader.go:336-343,586-608

关键验证：Go 测试均使用 -count=1；相关并发包使用 -race；SQLite FTS5 相关套件使用 -tags=fts5。
